## 自主是一种运行模式，不是模型的等级

新同事入职第一周，你可以放心让他整理共享盘里的临时文件夹，却不会让他独自签一份大额合同。不是因为他整理文件时更聪明，而是这两件事做错了以后，后果有多大、能不能及时发现、能不能挽回，完全不同。

**Human-out-of-the-loop**（人在环外）指运行过程中没有人逐步审批。无人逐步审批，最适合被理解为一种**经过验证的运行模式**，而不是一个模型能力等级。相同模型可以自主整理临时目录，却不适合在无人确认的情况下执行重大资产转移。决定因素不只是它答对问题的比例，还包括四样东西：

- **错误影响范围**：错了会波及多少对象、多少钱、多少人。
- **可检测性**：错了能不能被及时发现。
- **可恢复性**：发现之后能不能撤回、重做。
- **授权是否明确**：用户到底允许它做什么，边界写没写清楚。

这四样都不是模型的属性，而是**任务加上 harness** 的属性。同一个模型，放进一个写入可撤销、检查可执行、边界清楚的流程里，就可以放手；放进一个删除不可逆、结果没人核对的流程里，就不行。

“人在环外”也不等于人不在场。回想[第 19 讲](#lesson-19)的四个位置：自主运行时，运行中的审批撤掉了，任务开始前的边界、完成后的抽查和长期治理还在，而且要做得更扎实，因为它们成了人仅剩的控制点。

## 从一个很窄的任务开始

可以从一个很窄的任务开始：在隔离目录（一个只供这个任务读写、和其他文件分开的目录）里，把指定 CSV 转成标准格式，输出到新文件，保留原件。输入范围固定，成功条件清楚，写入可撤销，敏感数据不离开允许的边界。

## 放行之前的七道筛选

一个候选流程至少需要满足几项条件：

1. 授权覆盖明确；
2. 验收大部分可执行；
3. 操作遵循最小权限；
4. 失败能在造成过大影响之前被发现；
5. 状态可恢复，或动作具备幂等性；
6. 成本和时间有上限；
7. 对未知输入有安全停止路径。

有两个词需要解释。第 3 条的**最小权限**，是说只给任务刚好够用的权限：转换 CSV 的流程只需要读一个文件、写一个目录，就不该拿到删除权限或网络权限。它不能防止模型出错，但能限制出错时最多能坏到什么程度。第 5 条里的**幂等性**，是说同一个动作执行一次和执行多次，结果一样。比如“把订单状态设为已发货”执行两遍没有区别，“再下一单”执行两遍就是两单。

七条里有几条管的是“别出错”，更多管的是“出了错怎么办”：能不能及早发现，能不能退回，最多花掉多少，遇到意外会不会停。无人审批的流程里没有人在旁边随时喊停，这些事后的兜底就必须事先装好。

把这七条放到采购任务上试一试：查报价、算总价显然可以自主，那么真正下单呢？

## 置信度 0.96 说明不了什么

天气预报说“降水概率 30%”，背后是多年预报和实际天气的对账：说 30% 的那些日子里，大约三成真的下了雨。一个同事说“这事我有九成把握”，你却不知道他的“九成”平时准不准。前者是**校准**过的概率，后者只是一句话。

所以，尤其不要把模型自报“置信度 0.96”当作唯一的放行标准。这个数字可能只是语言输出，未必经过校准。更可靠的信号来自可测证据：

| 信号 | 它回答的问题 | 采购任务里的样子 |
| --- | --- | --- |
| 测试覆盖了哪些输入 | 这类输入以前验证过吗 | 三家报价的格式都在测试集里 |
| 独立读取是否匹配 | 结果和另一条来源对得上吗 | 下单后查询订单，总价确实是 7480 元 |
| 历史相似任务上的漏检率 | 检查器过去漏掉过多少错误 | 过去的采购记录里，总价检查漏过几次 |
| 多个检查器是否一致 | 不同角度的检查结论一样吗 | 预算检查和交期检查都通过 |
| 当前运行是否偏离已验证的分布 | 这次输入和验证过的像不像 | 突然出现第四家供应商，就属于偏离 |

最后一行值得多说一句。**分布**在这里指“验证时见过的那一类输入”。系统在三家供应商、一台笔记本的任务上验证过，不代表它在二十家供应商、五十台设备的任务上同样可靠。当前输入越不像验证过的样子，过去的成功率就越说明不了现在。

即使使用经过校准的概率，也应把错误损失纳入决策。同样一分的失败概率，在重排草稿和发送正式合同之间，意味着完全不同的风险：前者出错，损失是重排一次的几分钟；后者出错，可能是一份收不回的承诺。放不放手，看的是“失败的可能性”和“失败的代价”两样东西，而不是其中一样。

:::pitfall 小任务的成功率，不能直接搬到大任务上
在隔离目录里转换 CSV 连续成功了很多次，说明的是“这一类任务、这一套边界”下系统表现好。把它挪到“清理公司所有数据”上，输入、权限和可恢复性全都变了，原来的成功率就不再是证据。每扩大一次范围，都要为新出现的失败模式补上验收。
:::

## 分三步上线

新司机拿到驾照，通常先在熟悉的路上开，再上高速，再跑长途，而不是第一天就开夜车跑山路。自动化上线也可以这样分三步。

**影子模式**（shadow mode）是第一步：系统照常提出动作，但由已有流程执行，比较建议与真实决策。它像一个只看不动手的实习生，所有建议都记下来，和老员工的实际做法逐条对照。对照时要看的不只是“一致的比例”，更要看不一致的那些落在哪里：如果分歧集中在某一类输入上，比如带退货记录的订单，那么这一类就先不放手，其余的可以进入下一步。

## 知道什么时候停

最重要的停止规则是：**系统发现自己已经离开获得授权且经过验证的工作区间时，能够停下来。**这里的“工作区间”，就是前面那些条件一起圈出来的范围：授权覆盖的动作、验证过的输入、能核对的结果。对采购 agent 来说，区间就是三家供应商、一台笔记本、含税 7600 元以内、报价编号是核对过的那几个；冒出第四家供应商、数量变成两台、报价编号变了，都说明它已经走到了区间之外。区间之外不一定会出错，但此前的验证已经说明不了这里的情况，继续做下去，就是在没有证据的地方冒险。

离开区间的时刻，往往伴随着一个很诱人的“继续”的办法。无法确认写入是否成功时，不应不断重复发送：

| 情形 | 诱人的做法 | 应当的做法 |
| --- | --- | --- |
| 无法确认写入是否成功 | 再发一次 | 先查询状态；查不清就停下，报告“状态未知” |
| 无法辨认账户 | 挑一个最像的 | 停下，列出候选和各自的依据，请人确认 |
| 验证器之间出现无法解释的差异 | 取平均分 | 保留冲突，先查原因，查不清再升级 |

:::example 两个同名账户
财务助手收到指令“给王磊退款 300 元”（虚构），系统里却有两个叫王磊的客户，一个上周有退货记录，一个没有。挑“最像的那个”看起来很合理，可一旦挑错，钱就退给了别人。正确的做法是停下来，把两个账户和各自的依据列出来，请人确认。多等几分钟的代价，远小于一笔退错的款。
:::

成熟的自动化既知道如何继续，也知道何时继续会把不确定性变成真实损失。

这一部分最终建立的不是“模型从此不会错”，而是一条更扎实的完成链：用户目标被明确表达，执行受到边界约束，结果由适当证据支持，剩余的不确定性被如实暴露。接下来增加 agent 数量时，这条链不仅不能消失，还要面对更多信息交接和错误传播，[第 21 讲](#lesson-21)从五种架构讲起。

:::recap 小结
- 无人逐步审批是一种经过验证的运行模式，不是模型能力等级；决定能否放手的是错误影响范围、可检测性、可恢复性和授权是否明确。
- 从边界清晰的窄任务开始：输入固定、成功条件可查、写入可撤销、没见过的情况就停；把范围扩大一圈，风险会发生质变，小任务的成功率不能外推。
- 放行前逐条检查七个条件：授权明确、验收可执行、最小权限、失败能及早发现、可恢复或幂等、成本时间有上限、未知输入能安全停下；它们是工程筛选，不是安全证明。
- 模型自报的置信度可能只是语言输出；应看测试覆盖、独立读取、历史漏检率、检查器是否一致和是否偏离已验证分布，并把失败的代价一起算进去。
- 上线分影子模式、小范围自动、扩大覆盖三步，每一步都能退回；离开授权且验证过的区间时，系统要能自己停下，不重发、不乱挑、不取平均。
:::
