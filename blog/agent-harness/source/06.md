## 目标很克制：一个读得完的 harness

学开车通常先在空旷的场地里练，不急着上高速。这一讲的程序就是这样一块练习场：前面几讲的概念（循环、工具契约、结构化输出、验收）都会出现，但规模小到可以一口气读完，而且不会造成任何真实后果。

现在把前面的概念压缩进一个小例子。目标很克制：模型查询虚构供应商的报价，再向用户给出结论。工具只能读取一个固定的字典，既不能购买，也不能执行任意代码。这样我们可以把注意力放在**协议闭环**上：请求怎样发出，工具调用怎样被校验和执行，结果怎样回到模型手里，最后怎样验收。安全边界没有藏在一个复杂框架后面，每一道都能在代码里指出来。

先说清几个名词：

- **SDK**（软件开发工具包）：这里用的是官方的 `openai` Python 包。它只是一个客户端库，请求最终发到哪个服务，由参数 `base_url` 决定。
- 示例沿用 DeepSeek 当前官方文档中的 OpenAI 兼容接口和模型名称。所以**使用 OpenAI SDK，不意味着请求会发给 OpenAI**：`base_url` 指向 DeepSeek，请求就发给 DeepSeek。
- **密钥**从本地环境变量读取，不能写进仓库、前端静态资源或日志。

还要坦白一点：这个示例没有声称经过付费的在线端到端测试。默认的 mock 模式可以离线跑通；真实模式需要读者自己用低预算验证。[来源：DeepSeek 首次调用](https://api-docs.deepseek.com/)、[官方 OpenAI Python SDK](https://github.com/openai/openai-python)

程序大约两百行。代码块顶部有一排**大纲按钮**，点一下就跳到对应的定义。大纲里的十二个名字可以分成四组：数据（`VENDORS`、`GOAL`、`TOOLS`），边界（`dispatch()`、`verify()`、`base_url()`、`is_complete()`），模型（`MockModel`、`SDKModel`），循环与入口（`Budget`、`run()`、`main()`）。读代码之前，先看它们在一圈循环里各守哪一格：

```python
"""Bounded Python reference harness. Mock by default; live needs explicit --live.

No eval, shell, network tools, automatic retries or credential logging.
"""
from __future__ import annotations

import argparse
import asyncio
import json
import os
from dataclasses import dataclass
from urllib.parse import urlsplit

VENDORS = {
    "clay": {"price": 6800, "tax": 0.1, "delivery": "2026-10-03", "source": "quote-clay-v2"},
    "ink": {"price": 6400, "tax": 0.1, "delivery": "2026-10-12", "source": "quote-ink-v3"},
    "paper": {"price": 7100, "tax": 0.1, "delivery": "2026-10-04", "source": "quote-paper-v1"},
}
GOAL = (
    "虚构采购：买一台笔记本，含税预算7600元，2026-10-05前交付。"
    "核查三家本地报价，最终用JSON返回vendor,total,delivery,source。不是实际采购。"
)
TOOLS = [
    {"type": "function", "function": {
        "name": "lookup_vendor", "description": "读取虚构供应商报价与交期；无副作用",
        "parameters": {"type": "object", "properties": {
            "id": {"type": "string", "enum": list(VENDORS)}},
            "required": ["id"], "additionalProperties": False}}},
    {"type": "function", "function": {
        "name": "compute_total", "description": "本地计算含税总价",
        "parameters": {"type": "object", "properties": {
            "id": {"type": "string", "enum": list(VENDORS)},
            "quantity": {"type": "integer"}},
            "required": ["id", "quantity"], "additionalProperties": False}}},
]


def dispatch(call: dict) -> dict:
    if call.get("type") != "function":
        raise ValueError("unknown tool type")
    fn = call.get("function", {})
    name = fn.get("name")
    if name not in {"lookup_vendor", "compute_total"}:
        raise ValueError("tool not permitted")
    raw = fn.get("arguments")
    if not isinstance(raw, str) or len(raw.encode()) > 4096:
        raise ValueError("arguments too large or invalid")
    args = json.loads(raw)
    expected = {"id", "quantity"} if name == "compute_total" else {"id"}
    if not isinstance(args, dict) or set(args) != expected:
        raise ValueError("unexpected fields")
    if not isinstance(args["id"], str) or args["id"] not in VENDORS:
        raise ValueError("unknown vendor")
    vendor = VENDORS[args["id"]]
    if name == "lookup_vendor":
        return {"id": args["id"], **vendor}
    qty = args["quantity"]
    if type(qty) is not int or not 1 <= qty <= 3:
        raise ValueError("quantity policy: integer 1..3")
    return {"total": round(vendor["price"] * (1 + vendor["tax"]) * qty),
            "source": vendor["source"]}


def verify(content: str) -> dict:
    try:
        result = json.loads(content)
    except (ValueError, TypeError):
        return {"parse": False}
    if not isinstance(result, dict):
        return {"parse": False}
    return {
        "parse": True, "vendor": result.get("vendor") == "clay",
        "total": type(result.get("total")) is int and result.get("total") == 7480,
        "delivery": result.get("delivery") == "2026-10-03",
        "source": result.get("source") == "quote-clay-v2",
    }


def base_url(value: str) -> str:
    p = urlsplit(value)
    if p.scheme != "https" or not p.hostname or p.username or p.password or p.query or p.fragment:
        raise ValueError("base URL must be HTTPS without credentials/query/fragment")
    return value.rstrip("/")


def is_complete(checks: dict) -> bool:
    required = {"parse", "vendor", "total", "delivery", "source"}
    return set(checks) == required and all(value is True for value in checks.values())


class MockModel:
    def __init__(self):
        self.step = 0

    async def call(self, messages: list, tools: list) -> tuple[dict, int | None]:
        self.step += 1
        if self.step == 1:
            calls = [{"id": f"mock-{name}", "type": "function", "function": {
                "name": "lookup_vendor", "arguments": json.dumps({"id": name})}}
                for name in VENDORS]
        elif self.step == 2:
            calls = [{"id": "mock-total", "type": "function", "function": {
                "name": "compute_total", "arguments": '{"id":"clay","quantity":1}'}}]
        else:
            return {"role": "assistant", "content": json.dumps({
                "vendor": "clay", "total": 7480, "delivery": "2026-10-03",
                "source": "quote-clay-v2"})}, None
        return {"role": "assistant", "content": None, "tool_calls": calls}, None


class SDKModel:
    def __init__(self, key: str, base: str, model: str, thinking: bool):
        from openai import AsyncOpenAI
        import httpx

        self.client = AsyncOpenAI(api_key=key, base_url=base, max_retries=0, timeout=60,
                                  http_client=httpx.AsyncClient(follow_redirects=False))
        self.model, self.thinking = model, thinking

    async def call(self, messages: list, tools: list) -> tuple[dict, int | None]:
        if len(json.dumps(messages, ensure_ascii=False).encode()) > 32768:
            raise ValueError("context exceeds 32 KiB")
        response = await self.client.chat.completions.create(
            model=self.model, messages=messages, tools=tools, max_tokens=1200,
            extra_body={"thinking": {"type": "enabled" if self.thinking else "disabled"}},
        )
        if not response.choices or response.choices[0].finish_reason not in {"stop", "tool_calls"}:
            raise ValueError("incomplete model response")
        # Includes provider extra reasoning_content. Keep it in live history, never print it.
        message = response.choices[0].message.model_dump(exclude_none=True)
        # SDK response-only fields are not request history fields.
        message = {k: v for k, v in message.items()
                   if k in {"role", "content", "tool_calls", "reasoning_content"}}
        return message, response.usage.total_tokens if response.usage else None

    async def close(self):
        await self.client.close()


@dataclass
class Budget:
    calls: int = 0
    tools: int = 0
    tokens: int = 0
    usage_calls: int = 0


async def run(model, emit=print) -> dict:
    messages = [{"role": "user", "content": GOAL}]
    budget = Budget()
    seen_ids = set()
    for _ in range(3):
        budget.calls += 1  # Reserve before dispatch, not after response.
        message, tokens = await model.call(messages, TOOLS)
        if type(tokens) is int and tokens >= 0:
            budget.tokens += tokens
            budget.usage_calls += 1
        messages.append(message)
        calls = message.get("tool_calls", [])
        if not calls:
            checks = verify(message.get("content", ""))
            emit(json.dumps({"event": "verification", "checks": checks}, ensure_ascii=False))
            return {"passed": is_complete(checks), "calls": budget.calls,
                    "tools": budget.tools, "tokens": budget.tokens if budget.usage_calls == budget.calls else None}
        for call in calls:
            if budget.tools >= 4:
                raise ValueError("tool budget exhausted")
            if not call.get("id") or call["id"] in seen_ids:
                raise ValueError("duplicate/missing call ID")
            seen_ids.add(call["id"])
            budget.tools += 1
            try:
                result = dispatch(call)
            except (ValueError, TypeError):
                result = {"error": "tool contract or policy rejected"}
            # Whitelisted summaries only: no raw model text, arguments, headers or keys.
            emit(json.dumps({"event": "tool", "sequence": budget.tools,
                             "status": "rejected" if "error" in result else "ok"}))
            messages.append({"role": "tool", "tool_call_id": call["id"],
                             "content": json.dumps(result)})
    raise ValueError("model call budget exhausted")


async def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--live", action="store_true")
    parser.add_argument("--thinking", action="store_true")
    parser.add_argument("--base-url", default="https://api.deepseek.com")
    parser.add_argument("--model", default="deepseek-flash",
                        choices=["deepseek-flash", "deepseek-v4-pro"])
    parser.add_argument("--approve-destination", help="Must exactly equal normalized base URL")
    args = parser.parse_args()
    model = MockModel()
    if args.live:
        base = base_url(args.base_url)
        if args.approve_destination != base:
            parser.error("explicit --approve-destination required for this exact base URL")
        key = os.environ.get("DEEPSEEK_API_KEY", "")
        if not key or "\n" in key or "\r" in key:
            parser.error("set DEEPSEEK_API_KEY locally; never paste it in chat or commit it")
        print(f"LIVE destination={base}/chat/completions model={args.model}; "
              "3 calls / 1200 output tokens each / 4 local tools / 120s total; no retries")
        model = SDKModel(key, base, args.model, args.thinking)
    try:
        result = await asyncio.wait_for(run(model), timeout=120)
        print(json.dumps(result, ensure_ascii=False))
        return 0 if result["passed"] else 1
    except (Exception, asyncio.CancelledError):
        # Avoid SDK exception bodies containing sensitive echoed data.
        print("Run failed/cancelled/incomplete; raw provider error omitted. Usage may be unknown.")
        return 2
    finally:
        if isinstance(model, SDKModel):
            await model.close()


if __name__ == "__main__":
    raise SystemExit(asyncio.run(main()))

```

## 跟着一次运行走一遍

读代码最可靠的办法之一，是拿一个具体的输入，跟着它把程序走一遍，就像调试器单步执行。我们用默认的 mock 模式，也就是直接运行 `python harness.py`。

**MockModel** 是一个假模型：它不联网，不读 `messages`，只按固定剧本回复。第一次一口气提出三个 `lookup_vendor`，第二次提出 `compute_total(clay, 1)`，第三次交出最终 JSON。剧本固定，所以每一步的状态都能准确写出来：

1. **开始。** `messages` 里只有一条 user 消息，就是 `GOAL`；`Budget` 的各项计数都是 0。
2. **第 1 圈。** 先把 `budget.calls` 记为 1，再调用 `model.call()`。返回的 assistant 消息没有文字，只有三个工具调用，ID 分别是 `mock-clay`、`mock-ink`、`mock-paper`。这条消息原样追加进 `messages`。
3. **处理三个调用。** 对每一个：工具预算还没到 4，ID 非空且没出现过，于是计数加一，交给 `dispatch()`。三个都通过，返回三家的完整报价。每处理一个，屏幕上打印一行只含序号和状态的事件；结果作为 role 为 tool 的消息追加，`tool_call_id` 对上各自的 ID。此时 `messages` 共 5 条，`budget.tools` 为 3。
4. **第 2 圈。** `budget.calls` 为 2。剧本提出 `compute_total`，参数是 `{"id":"clay","quantity":1}`。`dispatch()` 检查数量在 1 到 3 之间，算出含税总价。这里有个细节：`6800 * 1.1` 在浮点数里其实是 `7480.000000000001`，`round` 把它变回整数 7480。验收器要求总价是整数，这一步不能省。`budget.tools` 变成 4，工具预算正好用满。`messages` 共 7 条。
5. **第 3 圈。** `budget.calls` 为 3。这次回复没有工具调用，只有一段 JSON。`run()` 把它交给 `verify()`，五项全部通过，打印验收事件，返回结果。`messages` 最终 8 条。
6. **收尾。** `main()` 打印结果，以退出码 0 结束。

```text
{"event": "tool", "sequence": 1, "status": "ok"}
{"event": "tool", "sequence": 2, "status": "ok"}
{"event": "tool", "sequence": 3, "status": "ok"}
{"event": "tool", "sequence": 4, "status": "ok"}

{"passed": true, "calls": 3, "tools": 4, "tokens": null}
```

有两处值得停一下。

第一，事件行里**只有序号和状态**，没有工具参数，也没有返回内容。这是故意的：代码注释写明，事件只输出白名单里的摘要，不输出模型原文、参数、请求头或密钥。日志要能复盘，但不能变成泄露渠道。

第二，最后一行的 `tokens` 是 `null`，不是 0。MockModel 不报告用量；`run()` 只有在**每一次**调用都报告了用量时，才给出 token 总数。只拿到一部分用量就加起来，会让费用看上去比实际少；宁可写“未知”，也不写一个偏小的数。

程序的退出码也分了三种：0 表示答案通过验收，1 表示给出了答案但验收未通过，2 表示运行失败、被取消或不完整。脚本或 CI 可以直接据此判断结果，不必去解析文字。

## 三处关键：dispatch、tool_call_id 和预算

读这段代码时，重点看三个位置。第一处是 `dispatch`：只有写在注册边界里的能力才能执行，工具名不会被传给 `eval`。第二处是 `tool_call_id`：结果必须对应模型请求的那一次调用，否则历史关系会断裂。第三处是循环预算：当模型持续请求工具时，系统有明确的停止机制，不会无限消耗余额。下面逐一展开。

### dispatch：只执行注册过的能力

模型交来的工具调用，本质上只是一段文字：一个工具名，加一串 JSON 形式的参数。它**可能**是对的，也可能编了一个不存在的工具，多塞一个字段，或者要买 999 台。`dispatch()` 把它当成不可信的输入，逐层检查，每一层都只做一件事。用配套测试 `test_policy` 里的那个调用走一遍：

注意第 3 层和第 5 层的写法。字段检查用的是 `set(args) != expected`，要求集合**完全相等**，多一个字段也不行；数量检查用的是 `type(qty) is not int`，而不是 `isinstance`。在 Python 里 `True` 也算 `int` 的实例，用 `isinstance` 就会让 `"quantity": true` 冒充数量 1 混过去。

还有一点：拒绝时写回给模型的，是一句统一的固定文字，不回显模型传来的参数。模型知道“被拒了”，但不知道具体哪一层；这是一个取舍，后面“想改它”一节会再谈。

### tool_call_id：结果要对得上请求

去餐厅点餐会拿到一个取餐号。三份餐同时做好时，靠号码才知道哪份是谁的。工具调用也一样：第 1 圈里模型一次提出了三个查询，三份结果写回时，每一份都要带上对应调用的 ID，也就是 `tool_call_id`。

少了这个对应，历史关系就断了：模型可能把 ink 的报价当成 clay 的。所以 `run()` 对 ID 的态度很强硬：ID 缺失或者重复，**整次运行直接停止**，而不是猜一个配对继续跑。猜错的配对会悄悄污染后面所有的决定，比停下来更糟。

顺带看一眼 `SDKModel.call()` 怎样处理模型的回复：它把返回消息只保留 `role`、`content`、`tool_calls`、`reasoning_content` 四个字段。前三个是下一次请求要带回的历史；最后一个就是[第 6 讲](#lesson-6)说的协议要求：开启 thinking 时要回传。代码注释写明，它只留在当前运行的历史里，从不打印。请求里 thinking 的开关也是显式写出的，默认关闭。

### 预算：先记账，再花钱

`Budget` 里有四个计数：模型调用次数、工具调用次数、累计 token、报告了用量的调用次数。上限写在 `run()` 里：最多 3 次模型调用（`range(3)`），最多 4 次工具调用。

有一行注释值得背下来：`budget.calls += 1  # Reserve before dispatch, not after response.` 意思是**先占预算，再发请求**。如果反过来，等回复回来才记账，那么一次中途失败的请求可能已经计费，却没有被算进去。工具也一样：计数在执行之前加一，被拒绝的调用同样占预算。

3 和 4 这两个数，恰好是 mock 剧本需要的量，一点余量都没有。这就带来一个很实际的问题：

## 护栏清单：每一道挡住什么

把散在代码各处的检查集中起来，就是下面这张表。读的时候，每一行都可以问自己一句：如果删掉它，会发生什么？

| 护栏 | 代码位置 | 挡住什么 |
| --- | --- | --- |
| 工具白名单 | `dispatch()` | 模型编造或越权的工具名；工具名只用来查表，不会被 `eval` |
| 参数是字符串且不超过 4096 字节 | `dispatch()` | 超长或畸形的参数拖垮解析 |
| 字段集合完全一致、供应商在枚举里 | `dispatch()` | 多带或漏带字段、不存在的供应商 |
| 数量是 1–3 的整数 | `dispatch()` | 业务不允许的数量，比如 999；`True` 冒充 1 |
| 拒绝变成观察 | `run()` 的 `except` | 一次坏调用让整个程序崩溃 |
| 调用 ID 非空且不重复 | `run()` 的 `seen_ids` | 结果对错调用，历史关系断裂 |
| 3 次模型调用、4 次工具调用，先记账再调用 | `run()` 与 `Budget` | 模型没完没了地请求，余额被耗尽 |
| 上下文不超过 32 KiB，输出上限 1200 token | `SDKModel.call()` | 历史无限增长；单次输出过长 |
| 回复必须以 stop 或 tool_calls 结束 | `SDKModel.call()` | 被截断的半截回复被当成完整答案 |
| 单次 60 秒、整体 120 秒、不自动重试 | `SDKModel`、`main()` | 卡住的请求；重试造成调用次数不清、不确定的动作被重复 |
| 只接受 HTTPS，目的地要显式确认，不跟随重定向 | `base_url()`、`main()`、HTTP 客户端 | 密钥被发往写错或不安全的地址 |
| 密钥只从环境变量读 | `main()` | 密钥出现在源码、命令行参数或仓库里 |
| 事件只打印白名单摘要，错误不打印原文 | `run()`、`main()` | 日志里出现模型原文、参数、请求头或密钥 |
| 最终答案必须是 JSON 且五项全真 | `verify()`、`is_complete()` | 关键词命中式的“通过”；缺字段的空答案 |

表的最后一行值得单独说。完整程序要求最终答案是 JSON，并逐项校验供应商、含税价、交付日期与证据 ID。它**不靠关键词包含**来判断：“不要选 clay”这句话也包含 clay，却不能当作正确推荐。`verify()` 里还有两处细节：总价要求 `type(...) is int` 且等于 7480，所以字符串 `"7480"` 或浮点数 `7480.0` 都不算；`is_complete()` 要求五个键一个不多、一个不少，并且全部为 True，所以空字符串、`{}`、`[]`、`null` 都过不了关，配套测试 `test_empty_rejected` 查的就是这几种。

也要看清它的边界：当前验证器只覆盖这一份固定的 fixture（虚构的报价数据）。扩展题目时，应该同时扩展验收合同，而不是让模型去迎合一个写死的答案。

时间与取消方面：完整代码同时设置了单次请求 60 秒和整项 120 秒的 deadline，可以用 Ctrl+C 取消。但本地取消**不保证** provider 停止计费：请求可能已经在服务端开始处理。自动重试是关闭的，一是让调用次数清清楚楚，二是避免把一个结果不确定的动作重复执行一遍。

最后，这个小程序有意没做的事：没有生产级的持久会话，也没有副作用恢复，程序中断就从头再来。Python 版采用非流式 SDK，让协议容易阅读；浏览器里的实验则用 JavaScript 实现了流式组装。如果要扩展出会写入、会下单的工具，仍然需要授权、幂等与事后核验。

:::pitfall 把 mock 跑通当成“能用了”
mock 模式的轨迹是固定的，没有任何随机的模型行为；它证明的是 harness 的接线没问题：调用能校验、结果能对号、预算能停、验收能判。即使换成真实模型并通过了五项检查，也只说明这道虚构题的验收条件被满足了，不代表完成了真实采购，也不代表系统在别的任务上可靠。
:::

除了图里这四处，还有几个常见的改动点：

- **加一家供应商**：在 `VENDORS` 里加一项，`TOOLS` 里的枚举会自动跟上（它用的是 `list(VENDORS)`）；但 `GOAL` 里写着“三家”，`verify()` 里写死了正确答案，都要一起看。另外，`MockModel` 第 1 圈会给 `VENDORS` 里的每一家各查一次：加到四家，四次查询就把 4 次工具上限用满，随后的 `compute_total` 是第 5 次，会撞上上限，mock 以 exit 2 结束。所以工具预算也要一起调。
- **让模型知道为什么被拒**：可以把 `dispatch()` 里那几句固定的拒绝原因（例如 `quantity policy: integer 1..3`）写回给模型，帮助它下一圈改正；浏览器版的 `dispatch` 就是这样做的，拒绝时写回的是具体哪一条契约没通过。只写你自己定义的固定文字，不要把模型传来的原始参数原样回显。
- **换一个服务**：用 `--base-url` 指定新地址，并用 `--approve-destination` 再输入一遍完全相同的地址。`--model` 只允许列表里的两个名字，请求里的 thinking 字段也是按 DeepSeek 文档写的，别的服务未必认它。

:::try 练习：没有可行方案时怎么办
把 clay 的交期改到截止日之后，比如 2026-10-06。这时三家都不满足条件：clay 晚到，ink 晚到，paper 含税 7810 元超出预算。请设计一个结构化的“无可行方案”结果，以及相应的验证器。

不能只改 fixture，还沿用固定的正确答案；也不能因为用户说了“推荐一家”，就硬选一家交差。
:::

一种可以参考的结果形状（字段名是示意）：

```json
{"vendor": null, "status": "no_feasible_option",
 "rejected": {"clay": "delivery 2026-10-06 > 2026-10-05", "ink": "delivery 2026-10-12 > 2026-10-05", "paper": "total 7810 > 7600"}}
```

对应的验证器要检查的，也就不再是“vendor 是不是 clay”，而是：`vendor` 为空，状态是约定的值，三家各有一条可以用 fixture 核对的拒绝理由。

这个反例把我们带入下一部分：任务进行很久、数据不断变化时，系统还能记住哪些约束，知道自己读的是哪个版本吗？

保存聊天记录很容易，让另一次模型调用在正确状态下继续工作却困难得多。模型看到的上下文、磁盘里的记录、当前正在运行的任务、以后可能复用的经验，具有不同的用途与生命周期。下一部分把它们拆开，讨论压缩、位置、检索、存储和技能如何协作。

:::recap 小结
- 最小可运行的 ReAct harness 只需要几样东西：固定的数据与工具定义、校验并执行调用的 `dispatch()`、带预算的循环 `run()`、独立的验收 `verify()`，以及管住目的地、密钥和时限的入口 `main()`。
- 使用官方 `openai` SDK 不等于请求发往 OpenAI；服务由 `base_url` 决定，密钥只从本地环境变量读取。
- `dispatch()` 把模型的调用当成不可信输入，逐层校验；拒绝以统一的观察写回，并照样计入预算。
- 每个工具结果都要用 `tool_call_id` 对上它的请求；ID 缺失或重复就停止运行，而不是猜一个配对。
- 预算先记账再调用；3 次模型调用、4 次工具调用给出了清楚的花费上界，代价是一圈只做一件事的模型可能跑不完。
- 验收要求 JSON 且五项全真，不靠关键词匹配；改数据、改预算、加工具时，要同时改验收合同和对应的护栏。
:::
