“给 agent 加记忆”听起来像接一个数据库，实际先要明确保存的内容是什么、以后如何使用。一个有用的内容分类是事实记忆、经历记忆和程序性记忆；但内容类型与存储位置是两条不同的坐标轴。

事实记忆描述世界或任务中的状态，例如“当前预算是 8000 元”“项目使用 Python 3.12”“用户明确偏好可编辑文件”。经历记忆记录某一次发生过的事，例如“9 月 30 日查询供应商 B，接口返回旧版本，改用带版本参数的查询后解决”。程序性记忆则提炼可重复的做法，例如“比较报价前先核对有效日期，再算含税总价，最后检查交付约束”。

同一件事可以同时产生三种内容。一次采购比较结束后，当前预算属于事实，接口异常与解决过程属于经历，经过验证的比较流程属于程序。不要把三者粗暴混成“经验总结”。否则以后检索“预算多少”时，模型可能从旧案例中找到一个已经过期的数字；检索“如何排错”时，又只得到结果而没有过程。

另一条轴是信息存在何处：模型参数、外部存储、当前上下文。事实可以在参数里，也可以在数据库里；程序可以体现于模型能力，也可以写成脚本或 skill；经历往往外置，但本轮上下文里同样可能暂存。RAG 原论文明确把参数记忆与非参数记忆结合起来，因此“事实由权重负责，经验才需要外置”的说法不成立。[来源：Retrieval-Augmented Generation](https://arxiv.org/abs/2005.11401)

记忆还需要时间与证据。与其写“B 的交付速度快”，不如写“在教学报价 quote-B-v2 中，交付日期为 2026-10-08；该事实只对这份报价有效”。前一种表述容易在后续任务中被泛化成供应商长期属性，后一种表述保留了适用边界。对于用户偏好也一样，一次选择最便宜的方案，不足以推断用户永远只看价格。

Reflexion 展示了把反馈写入文本记忆、供之后尝试使用的路径，它不要求更新基础模型权重。这种适应可以对任务有用，但应描述为系统利用了外部反馈，不能声称模型权重已经学会新知识。Generative Agents 则研究经历、反思与规划对行为模拟的作用，其目标与可靠工程执行不同，借鉴机制时也要保留任务边界。[来源：Reflexion](https://arxiv.org/abs/2303.11366)、[Generative Agents](https://arxiv.org/abs/2304.03442)

写记忆可以采用一个小型门槛：这条内容将来有可能复用吗？它是否有来源？是否需要有效期？是观察还是推测？是否包含不必要的敏感信息？不能因为保存空间便宜，就把所有内容永久写入。无选择地积累会增加过期信息、重复内容与检索噪声，也让纠错与删除变得困难。
